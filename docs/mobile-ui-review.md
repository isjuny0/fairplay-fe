# 모바일 화면 확인

2026-11-03 기준 로컬 미리보기를 Chrome에서 확인했습니다. 320·390·768px 너비로 기본 경로 25개를 캡처하고, 리더·팀원·관리자 역할별 경로를 자동 검증합니다. 작은 가로 화면은 640×360px에서 알림·할 일 팝업을 확인합니다.

## 확인 범위

| 영역 | 화면 |
| --- | --- |
| 진입 | 서비스 소개, 로그인, 스페이스 선택 |
| 개인 | 알림함, 헤더의 알림·할 일 팝업 |
| 스페이스 | 홈, 공지 목록·상세·작성 |
| 팀 | 홈과 캘린더, 작업 보드·목록·타임라인·상세·등록 |
| 자료 | 산출물 목록과 등록 유형 선택·문서 작성, 회의록 목록·상세·등록, 팀 자료 검색 |
| 팀 운영 | 팀원 관리, 팀 설정, 동료 평가, 중간 피드백, 기여도 리포트 |
| 스페이스 운영 | 팀 관리, 참여자 관리, 동료 평가 관리, 리포트 관리, 스페이스 관리, 팀원 수행 상세 |

기여도 리포트는 빈 상태와 공개된 결과를 모두 확인합니다. 팀 캘린더는 날짜 선택과 일정 등록 창을 열어 확인합니다. 표와 타임라인은 해당 영역 안에서 가로 스크롤하며, 페이지 전체에는 가로 스크롤이 생기지 않는지 확인합니다.

## 개선 내용

- 모바일 입력 글자를 16px로 지정해 iOS의 작은 입력 글자 자동 확대 조건을 피합니다.
- 주요 실행 버튼, 알림·할 일 버튼, 읽음 버튼, 모바일 메뉴와 평가 점수 선택 영역의 높이를 최소 44px로 확보합니다.
- 팝업의 높이를 동적 화면 높이에 맞추고, 넘치는 목록은 안에서 스크롤합니다. 할 일 카드의 음수 여백을 모바일에서 제거해 오른쪽이 잘리지 않게 합니다.
- 공지 상세의 작성자·등록일을 모바일에서는 두 줄의 정보 행으로 배치합니다.
- 타임라인의 고정 작업명 칸을 144px로 줄여 날짜 막대도 함께 보이게 합니다. 작업명은 두 줄까지 표시하고, 모바일에서는 열 너비 조절기를 숨깁니다.
- 알림함으로 이동할 때 이전 스페이스·팀 문맥을 전달합니다. 팀에서 들어온 경우 모바일 메뉴를 펼쳐 팀 메뉴로 돌아갈 수 있으며, 선택된 팀 메뉴는 표시하지 않습니다.
- 작성 창 하단 버튼에 기기의 안전 영역 여백을 적용합니다.

## 재확인

`npx playwright test tests/e2e/mobileUsability.spec.js`로 기본 화면의 가로 넘침, 팝업의 카드 잘림과 화면 경계, 타임라인 가로 이동, 공지 메타정보, 입력 글자 크기, 저장 버튼 접근, 알림함에서 팀으로 복귀하는 동선을 검증합니다.

Chrome의 화면 크기 조정과 터치 환경 모방으로 확인했습니다. 실제 iOS Safari의 화면 키보드·안전 영역·브라우저 UI 변화는 실기기에서 별도 확인이 필요합니다.

## 글자 겹침·줄바꿈 재점검 (2026-11-04)

기본 경로와 작업 보기 전환을 포함한 28개 화면을 320·390·545·768·1024·1440px에서 캡처했습니다. 공지·회의록·산출물·작업 작성, 위젯 추가, 알림·할 일 팝업, 공개 리포트는 320·545·768·1440px에서 별도로 열어 확인했습니다.

- 스페이스 홈의 고정된 제목·소개 행 높이와 줄 수 제한을 제거했습니다. 제목과 버튼이 길어져도 소개 문구는 그 아래로 내려가며, 상단의 불필요한 예약 여백도 줄였습니다.
- 모바일 메뉴의 현재 위치와 펼치기 안내를 각각 한 줄로 표시합니다. 프로젝트·팀 이름은 남은 너비를 사용하며, 메뉴 영역의 높이는 내용에 맞춥니다.
- 팀 홈의 세 실행 버튼은 글자를 쪼개는 대신 버튼 단위로 다음 줄에 배치합니다.
- 화면 제목·본문·도움말은 한국어 단어를 우선 유지하고, 화면보다 긴 이름과 주소는 필요한 경우 줄바꿈합니다.
- 타임라인의 날짜와 ‘오늘’ 표시는 서로 다른 높이에 배치하고, 첫날에도 ‘오늘’ 글자가 눈금 영역 밖으로 잘리지 않게 합니다.

`tests/e2e/textLayout.spec.js`는 320·390·545·720·768·1024·1440px에서 긴 스페이스 이름·소개, 버튼 문구, 모바일 메뉴, 타임라인 글자의 실제 배치와 잘림을 검증합니다. 긴 주소와 한국어 단어의 줄바꿈, 월 첫날 경계도 포함합니다.

검증 결과: 단위 187개, 관련 화면·기능 회귀 168개 통과. 최종 줄바꿈 변경 이후 신규 배치 검사 24개·기존 모바일 검사 20개·마크다운 검사 5개를 함께 실행해 49개 모두 통과했습니다. 프로덕션 빌드와 `git diff --check`도 통과했습니다.

### 모바일 정보 배치 추가 점검

469px에서 제보된 메뉴와 공지 목록을 기준으로 27개 화면을 320·390·469·600·720px에서 다시 확인했습니다. 글자 충돌뿐 아니라 제목·메타정보의 시작선, 카드 안의 아이콘 위치, 짧은 문구의 불필요한 줄바꿈을 함께 점검했습니다.

- 스페이스·팀 메뉴의 현재 화면명, ‘메뉴’, 화살표를 하나의 가로 컨트롤로 표시합니다. 펼침 상태는 화살표 회전과 `aria-expanded`로 유지합니다.
- 모바일 공지 요약·목록에서는 제목 아래 작성자·등록일을 한 묶음으로 왼쪽 정렬합니다. 긴 작성자 이름은 줄바꿈하며, 날짜가 다음 줄로 내려가도 제목의 시작선을 유지합니다. 데스크톱에서는 기존 열 배치를 사용합니다.
- 모바일 스페이스 선택 카드의 역할·팀 구성 상태를 이름 아래 왼쪽에 맞춥니다. 내 팀 카드의 이동 아이콘은 팀명·인원과 같은 행을 유지합니다.
- 아주 좁은 화면의 기간 정보는 항목명 아래에서 읽으며 종료일과 D-day·마감 표시는 함께 이동합니다. 내 팀 이동 버튼도 새 행에서는 왼쪽에 맞춥니다.
- 모바일 참여자 관리 카드의 항목명과 값을 왼쪽에 맞추고, 400px 이하의 평가·리포트 단계 표시는 한 줄에 두 단계씩 배치합니다.
- 팀 홈 진행률 카드의 그래프·설명·기준 시각을 같은 중심선에 놓습니다. 모바일에서는 내용에 맞춰 카드 높이가 늘어나 하단 버튼이 카드 밖으로 밀리지 않게 합니다.

`tests/e2e/mobileAlignment.spec.js`는 공지 정보의 시작선과 순서, 내 팀 카드 아이콘, 기간의 가로 잘림, 스페이스 카드 정보, 참여자·평가 단계 배치를 검증합니다. 기존 `textLayout.spec.js`에도 469px와 메뉴 문구의 한 줄 배치 검사를 추가했습니다.

추가 점검 검증 결과: 관련 브라우저 검사 173개 통과, 진행률 카드의 최종 수정 후 모바일 정렬·팀 홈 검사 40개 통과. 단위 187개, 프로덕션 빌드와 `git diff --check`도 통과했습니다.
