# 화면별 기능과 API 연동

[README로 돌아가기](../README.md) · [공통 API 연동과 오류 처리](api-integration.md)

## 화면 진입 흐름

- `/`: Fairplay 소개 메인. 작업보드·산출물·리포트 예시를 탭으로 선택합니다. 소개 예시는 API를 요청하지 않으며 실제 사용자 데이터가 아닙니다.
- `/login`: 기존 Google 로그인 화면. 인증이 완료되면 `/main`의 스페이스 목록으로 이동합니다. 보호된 상세 화면에서 로그인으로 이동했다면 원래 주소로 복귀합니다.
- `/main`: 로그인한 사용자의 스페이스 목록.

소개 예시는 자동 전환 없이 직접 선택할 때만 페이드 전환됩니다. 데스크톱 창은 16:9 비율이며, 좁은 화면에서는 내용이 잘리지 않도록 최소 높이를 유지합니다. 운영체제의 모션 감소 설정에서는 전환 효과를 생략합니다.

스페이스 목록에서는 승인된 팀 가입 정보를 기준으로 `팀 리더`·`팀원`·`참여자`를 구분합니다. 팀 미가입·가입 승인 대기·반려 상태는 `참여자`이며, 관리자는 별도로 표시합니다. 팀 목록 응답에 가입 정보가 없으면 팀 상세 API로 확인하고, 확인 실패를 미가입으로 표시하지 않습니다. `참여 중` 필터는 관리자가 아닌 스페이스 참여 전체를 뜻합니다.

내 스페이스 목록에는 기존 검색·필터·목록 디자인을 유지하는 왼쪽 사이드바가 있습니다. 역할별 보기는 본문의 역할 필터와 연동되며, 생성·코드 참여는 기존 모달을 사용합니다. 내 공간 바로가기는 승인된 가입 팀이 있으면 팀명과 이름 첫 글자를 표시하고 해당 팀 홈으로 바로 이동합니다. 소속 팀이 없으면 스페이스명을 표시하고 스페이스 홈으로 이동합니다. 팀 정보 조회 실패 시 목록에서 다시 시도할 수 있으며, 720px 이하에서는 접을 수 있는 상단 메뉴로 표시합니다.

## 팀 홈과 일정

팀 홈 헤더 아래의 ‘지난 확인 이후’ 브리핑은 미확인 작업·댓글·자료 변경 중 최대 두 건을 강조합니다. 첫 이용은 ‘최근 7일 팀 소식’, 확인 이력이 있으면 마지막 확인 시각을 표시합니다. 전체 변경과 주요 소식 건수를 구분하고, 접힌 상태에서도 작업명을 강조한 자연어 변경 문장을 항목별로 표시해 바로 이동할 수 있습니다. ‘모든 변경 보기’로 전체 항목과 발생 시각을 펼칩니다. 같은 작업의 변경은 한 항목으로 묶이고 기존 작업 상세나 자료 원문으로 이동합니다. 상세로 이동한 뒤 브라우저 뒤로 가기로 돌아오면 해당 방문의 펼침 상태와 위치를 복원합니다. 보조 설명은 마감 변경 전후·남은 시간·새 댓글 수 등 추가 사실이 있을 때만 표시합니다. 자료 링크는 팀 자료 주소의 `?deliverableId=`로 목록 페이지·검색 조건과 무관하게 해당 자료를 엽니다.

브리핑은 `GET /api/teams/{teamId}/briefing`으로 조회하고 ‘N건 모두 확인했어요’ 버튼을 눌렀을 때만 응답의 `ackToken`을 `POST /api/teams/{teamId}/briefing/acknowledge`로 전송합니다. 성공하면 짧은 확인 완료 안내로 축소하며 다음 방문에 다시 표시하지 않습니다. 확인 실패는 카드를 유지하고, 만료된 토큰은 다시 조회하도록 안내합니다. 새 변경이 없거나 브리핑 조회에 실패하면 다른 위젯에 영향을 주지 않고 브리핑만 표시하지 않습니다. 생성형 AI 호출·채팅·작업량 분석은 포함하지 않으며 기존 팀 자료 검색은 유지합니다.

저장된 위젯 설정이 없으면 팀 홈에 캘린더 → 지금 확인할 작업 → 팀 전체 진행률 순으로 표시합니다. 위젯 편집에서 내 기여도·다가오는 작업·내 작업 현황·평가·리포트·팀원·메모·작업 상태 요약을 추가하고, 드래그나 이동 버튼으로 순서를 바꾸거나 제거할 수 있습니다. 진행률은 본인 작업 현황 API를, 내 기여도는 공개된 기여도 리포트 API를 사용합니다. 제목 옆 물음표에서 지표 계산 기준을 확인하며, 계산 불가 값이나 공개 전 종합점수를 0점으로 대체하지 않습니다.

팀 홈 캘린더에는 회의·발표 등 팀 공유 일정을 직접 등록합니다. 날짜를 눌러 일반(하루)·기간·반복(매주·매월·매년)·다중 날짜 일정과 시간·카테고리·메모를 추가·수정·삭제합니다. 월간 보기에는 일정 점을, 2주 보기에는 날짜별 최대 다섯 개의 일정 제목을 최소 12px로 표시합니다. 좁은 캘린더에서는 제목 대신 간결한 일정 표시를 사용하며 날짜를 선택해 상세를 확인합니다. 월·연도 제목을 눌러 월별·연도별로 이동할 수 있습니다. 일정은 팀 공유 일정 API로 조회·저장하며 현재 팀원 모두가 수정·삭제할 수 있습니다. 월간은 인접 날짜를 포함한 표시 구간을, 2주 보기는 14일을 조회합니다. 종일 일정의 종료 일시는 다음 날 00:00으로 보내고, 반복·다중 날짜는 하나의 일정으로 저장합니다. 수정·삭제 시 version을 보내며 충돌하면 입력 내용을 유지하고 최신 일정 확인을 안내합니다. 팀 삭제 동의 중에는 일정 조회만 가능합니다. 위젯 배치와 빠른 메모는 개인 홈 설정 API로 내 계정에 저장합니다. 메모는 저장 버튼으로 반영하며 미저장 상태에서 화면을 떠나면 안내합니다. 미리보기는 같은 API 경로를 예시 저장소에서 처리합니다. 기존 브라우저 전용 일정은 팀 공유 자료로 자동 업로드하지 않습니다.

위젯 추가 창에서도 각 항목의 추가·제거를 바로 전환할 수 있습니다. 추가된 항목은 제거 동작과 선택 상태를 표시하고 재추가하면 기존 위젯 뒤에 배치합니다. 저장 중에는 중복 조작을 막으며 실패하면 구성을 보존하고 창 안에서 안내합니다. 메모에 미저장 입력이 있으면 제거 전에 확인하고, 저장된 메모는 위젯을 제거해도 보존합니다.

위젯의 ‘추가’를 누르면 저장 성공 후 선택 창을 닫고 바로 화면 편집 모드로 이어집니다. 새로 추가한 위젯을 잠시 강조하고 해당 위치로 이동해 이동 손잡이에 초점을 둡니다. 순서를 조정하고 상단의 ‘편집 완료’로 마칩니다. 저장 실패 시에는 선택 창과 기존 구성을 유지하며, ‘완료’·닫기·Escape는 편집 모드를 새로 열지 않고 선택 창만 닫습니다.

## 사이드바와 화면 전환

워크스페이스 사이드바는 `팀 작업 / 평가·리포트 / 팀 관리` 세 그룹으로 구성하며, 메뉴를 접거나 추가 단계를 거치지 않고 이동할 수 있습니다. 현재 메뉴는 연한 초록색 배경과 선명한 초록색 글씨로 표시합니다. 주요 실행 버튼은 초록색을 유지하고, 역할·작업 상태는 구분되는 연한 배경과 진한 색 글씨·상태 점을 사용합니다. 팀 홈의 마감 지연 아이콘은 연한 빨간 배경을 사용하며 기존 역할별 접근 권한은 유지합니다.

스페이스 목록과 워크스페이스 사이드바는 동일한 너비·좌우 여백을 사용합니다. 공간·팀 전환은 아이콘과 이름이 있는 선택 상자에서 제공하며, 펼친 목록은 현재 선택을 초록색·체크 표시로 구분합니다. 방향키·Home/End로 이동하고 Enter로 선택, Escape나 바깥 클릭으로 닫을 수 있습니다. 긴 이름은 펼친 목록에서 전체 내용을 확인할 수 있습니다.

## 작업 보드와 상세

작업 등록·수정은 모바일·데스크톱 모두 `작업 내용 → 작업 계획 → 담당자 배분`의 세 단계로 진행합니다. 제목·설명, 예상 시간·시작일·마감일, 담당자·배분율을 나누어 입력하며 현재 단계의 검증을 통과하면 다음으로 이동합니다. 마지막 단계에서만 저장하고 이전으로 돌아가도 입력을 유지합니다. 작업 설명란은 모달 높이에 맞춰 확대하고 낮은 화면에서는 줄어듭니다. 수정 시에는 기존 제목·설명·일정·담당 비율을 그대로 불러오고 마지막 단계의 저장 전 확인에서 변경 내용을 확인합니다. 등록·수정은 같은 모달 크기와 설명란 높이를 사용합니다. 예상 시간은 기본 30분이며 30분씩 증감하거나 직접 입력합니다. 생성·수정 요청은 `weight` 대신 `estimatedMinutes`를 보내고, 서버가 30분당 가중치 1로 계산합니다. 조회 시 `estimatedMinutes`를 우선 표시하며 이전 응답은 `weight × 30`분으로 환산합니다.

작업 상태색은 할 일 하늘색·진행 중 공통 초록색·수정 중 노란색·완료 회색으로 통일합니다. 보드뿐 아니라 작업 상세·관리자 수행 상세에서도 같은 공통 색상을 사용합니다. 목록 배지와 타임라인은 밝은 배경에 대비되는 글씨를 사용하고 상태명·기호도 함께 유지합니다. 마감 지연은 코랄색, 시작 예정일 경과는 노란색으로 구분합니다. 목록의 마감 지남 배지와 날짜도 팀 홈 마감 지연 아이콘과 같은 빨간색을 사용합니다.

작업은 보드·목록·타임라인으로 확인합니다. 이전 작업 캘린더 주소나 저장된 캘린더 보기 설정은 목록으로 전환하며 검색·필터 조건을 유지합니다.

담당자는 수행 설명과 연결 산출물을 갖춘 작업을 직접 완료합니다. 공동 작업은 담당자 전원의 수행 설명이 필요합니다. 완료 후에는 담당자가 `DONE → REVISING`으로 전환해 수정하고 다시 완료하며, 수정 중인 작업은 완료 집계에서 제외됩니다. 최종 평가 마감 이후에는 완료·재수정이 제한됩니다. AI 검토 조회·실행은 현재 담당자만 할 수 있습니다.

작업 상세의 하단에서 댓글을 조회·작성합니다. 현재 승인된 팀원이면 담당 여부와 관계없이 이용할 수 있고 수정·삭제는 작성자 본인만 가능합니다. 댓글은 일반 텍스트 1~2,000자로, 작성 시각 순서로 20개씩 조회합니다. 작업 완료·최종 평가 마감 후에도 이용할 수 있으며 팀 삭제 동의 중에는 조회만 가능합니다. 댓글은 작업 상태·버전·활동 시각·AI 검토·기여도에 영향을 주지 않습니다. 실제 화면은 GET/POST `/api/tasks/{taskId}/comments`, PATCH/DELETE `/api/task-comments/{commentId}`를 사용하고 미리보기에서도 같은 권한과 동작을 제공합니다.

## 팀 회의록

승인된 팀원은 사이드바의 `팀 작업 > 회의록`에서 회의 기록을 공동 관리합니다. 목록은 `/spaces/{spaceId}/teams/{teamId}/meeting-minutes`, 상세는 그 뒤의 `/{meetingMinuteId}` 경로이며 20개씩 회의일시 최신순으로 조회합니다. 작성자·리더 여부와 관계없이 승인 팀원 모두 등록·수정·삭제하며, 관리자 역할만으로는 접근할 수 없습니다.

등록·수정 모달은 `기본 정보 → 회의 기록` 두 단계로 이동합니다. 회의 기록은 하나의 마크다운 편집기에 `## 안건`, `## 내용`, `## 결정사항` 템플릿을 기본 제공하며 작성 도구·미리보기·이전 이동 시 입력을 유지합니다. 저장 시 세 구분 제목을 기준으로 기존 agenda/content/decisions에 나누어 보내고 항목별 길이 제한을 적용합니다. 구분 제목 누락·중복이나 제목 위의 원문은 저장 전에 안내하여 내용을 버리지 않으며, 빈 기록과 기본 템플릿만으로도 저장할 수 있습니다. 기존 회의록의 원문·공백·변경하지 않은 줄바꿈을 보존하고 수정한 필드만 전송합니다. 새 회의의 날짜는 한국 기준 오늘, 시간은 `00:00`이며 저장된 회의일시는 수정 시 보존합니다. 참석자는 현재 선택 가능한 인원 수를 기준으로 `선택 인원 / 전체 인원`을 표시하고, 이전 참석자는 별도로 구분합니다. 제목은 1~100자, 안건·결정사항은 각 5,000자, 논의 내용은 20,000자, 참석자는 최대 100명입니다. 제목과 일시만 필수이고 본문·참석자를 비워도 저장할 수 있습니다. 탈퇴한 참석자 기록은 편집 시 유지하거나 제거할 수 있습니다. HTML·스크립트·이미지·임베드는 실행하지 않습니다.

GET/POST `/api/teams/{teamId}/meeting-minutes`, GET/PATCH/DELETE `/api/meeting-minutes/{meetingMinuteId}`를 사용합니다. PATCH는 바뀐 필드와 `expectedVersion`만 보내며 DELETE는 버전을 쿼리로 전달합니다. 수정 충돌은 입력을 보존하고 최신 변경 항목을 비교·확인한 후에만 다시 저장합니다. 삭제 충돌도 자동 재시도하지 않습니다. 실제 API 오류를 예시 성공으로 바꾸지 않으며 `/preview/...`에서는 서버 요청 없이 같은 계약을 로컬 상태로 확인합니다.

## 스페이스 공지사항

스페이스 홈에서 고정 우선 공지 3개를 확인하고, 스페이스 화면의 사이드바에 있는 `공지사항`에서 전체 목록과 상세로 이동합니다. 팀 홈·작업·산출물 등 팀 내부 화면의 사이드바에는 공지사항 메뉴를 표시하지 않습니다. `/spaces/{spaceId}/announcements` 목록은 20개씩 조회하며 페이지를 주소에 보존합니다. 화면에는 현재 페이지와 이전·다음 버튼을 표시하고, API의 `totalCount`로 마지막 페이지를 판단합니다. 상세 주소는 `/spaces/{spaceId}/announcements/{announcementId}`입니다.

모든 역할의 공지는 흰 배경과 얇은 구분선의 같은 게시판을 사용하며 구분·제목·작성자·등록일을 별도 열에 표시합니다. 중요 공지는 구분 칸의 확성기 아이콘과 상세 화면의 `중요` 표시로 구별하고, 홈 요약에도 같은 행 디자인을 사용합니다. 목록과 상세의 새로고침 버튼 및 목록 건수 문구는 표시하지 않습니다. 검색창은 목록 위 왼쪽에 배치하고, 상세에서는 `목록으로` 버튼으로 돌아갑니다. 좁은 화면에서는 작성자를 오른쪽 별도 칸, 날짜를 아래에 배치합니다. 검색은 현재 페이지(최대 20개)의 제목·작성자만 대상으로 하며 입력창에 범위를 명시합니다. 검색어 `q`와 페이지를 주소에 보존하고 서버 API에는 기존 `page`·`size`만 전송합니다.

현재 스페이스의 USER·MANAGER 회원은 조회하고 MANAGER만 등록·수정·삭제합니다. 팀 리더 권한은 공지 관리 권한을 추가하지 않습니다. 제목은 앞뒤 공백 제거 후 1~100자, 본문은 1~5,000자이며 줄바꿈을 유지합니다. 중요 공지는 목록 상단에 우선 표시합니다. 관리자는 공지당 문서 파일을 최대 10개까지 첨부할 수 있습니다. 스페이스 회원은 목록에서 첨부를 다운로드할 수 있으며, 여러 파일은 ZIP으로 받습니다. 상세에서는 파일을 개별 다운로드합니다.

GET/POST `/api/spaces/{spaceId}/announcements`, GET/PATCH/DELETE `/api/spaces/{spaceId}/announcements/{announcementId}`를 사용합니다. 목록 응답은 `{items,totalCount}`이며 각 공지 응답에 `attachments`가 포함됩니다. PATCH는 제목·본문·고정 여부·`expectedVersion` 전체를 보내고 DELETE는 버전을 쿼리로 보내며 성공 본문은 없습니다. 버전 충돌 시 수정 입력을 보존하고 최신 내용 비교·재확인 뒤에만 다시 저장합니다. 삭제는 복구할 수 없음을 확인받으며 충돌 후 자동 재삭제하지 않습니다. 예시 화면은 `/preview/...`에서 같은 계약을 로컬 저장소로 처리하며 서버를 호출하지 않습니다. 기준: [스페이스 공지사항 도메인 계약](https://app.notion.com/p/4052567033ac81c7b88ed1fd33dbb119).

## 팀 자료 검색

승인된 팀원은 `팀 자료 검색`에서 질문·답변·근거 인용문과 자료 준비 현황을 확인합니다. 팀 홈과 산출물 목록에서도 진입합니다. 질문은 1,000자 이내이며 최근 질문과 답변 한 쌍을 표시합니다. 다른 팀 화면에 다녀와도 같은 팀의 마지막 답변과 질문 초안을 화면 메모리에서 복원하며, 새로고침하면 초기화됩니다.

POST `/api/teams/{teamId}/rag/questions`, GET `/api/teams/{teamId}/rag/index-status`는 실제 백엔드에 연결합니다. 서버의 `enabled`와 준비 상태에 따라 질문 가능 여부를 표시하며, 오류를 예시 답변으로 대체하거나 질문을 자동 재전송하지 않습니다. 팀 자료 검색 화면에 들어오거나 자료 목록의 페이지를 이동하거나 브라우저 창에 다시 포커스할 때 자료 준비 상태를 조회합니다. 검색이 활성화되어 있고 준비 중인 자료가 있으면 `자료 상태 새로고침` 버튼으로 다시 조회할 수 있습니다.

데스크톱 오른쪽에 팀 자료 목록을 상시 표시하고 같은 패널에서 목록과 원문을 오갑니다. 기존 준비 현황 모달은 제공하지 않습니다. 목록에는 제목·준비 상태·실패 사유와 새로고침·페이지 이동을 제공하고, 원문에서 돌아와도 페이지·스크롤 위치를 유지합니다.

GET `/api/teams/{teamId}/rag/sources/{deliverableId}?expectedVersion=…`로 근거를 조회합니다. TEXT·TXT·MD는 정규화한 원문, PDF는 선택한 페이지의 추출 텍스트, DOCX는 본문·단순 표의 추출 텍스트를 표시합니다. PDF 인용을 열 때는 `pageNumber`도 전달합니다. 답변 근거에서 열면 해당 인용 위치를 강조합니다. 목록 또는 질문 응답의 자료 버전을 보내며, 버전 변경·삭제·권한·읽기 실패는 오류로 표시합니다. TEXT·TXT·MD는 검색 준비와 별도로 열 수 있고, PDF·DOCX 근거 화면에는 같은 버전에서 추출해 저장한 텍스트가 필요합니다. 파일은 다운로드 후 자료 ID·팀·버전을 확인한 뒤 원본 저장을 시작합니다.

질문은 오른쪽 말풍선, 답변은 본문으로 표시하고 입력창은 화면 하단에 유지합니다. 현재 질문·답변 한 쌍만 표시하며 새 질문을 보내면 교체합니다. 같은 팀으로 돌아오면 마지막 답변과 질문 초안을 복원합니다. 각 검색 요청은 해당 질문만 보냅니다. Enter로 전송하고 Shift+Enter로 줄바꿈하며 한글 조합 중 Enter는 전송하지 않습니다. 실패하면 질문을 입력창에 복원합니다. 근거 원문은 데스크톱에서 오른쪽에, 좁은 화면에서는 닫을 수 있는 별도 패널로 표시합니다. `/preview/.../materials-search`는 같은 경로의 목업과 예시 답변을 사용하고 자료 검색 상황은 공통 미리보기 설정에서 선택합니다.
